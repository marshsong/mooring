# Mooring 拴马桩

**把手机拴在电脑边 —— 由电脑执行管控的安卓屏幕自律工具。**

任意 App 都能管，包括藏在微信里的那个。

规则放在电脑上，执行落在手机上。

## 解决什么问题

短视频产品是被人性弱点精心设计出来的。抖音、B 站可以卸，但总有一些 App 卸不掉——微信是工作工具，视频号就焊在里面，入口关不严；放眼国际，Instagram 也是一个聊天工具里焊着 Reels。

所有自律 App 都败在同一个地方：**钥匙和锁在同一台设备上**。冲动上头时，点两下"忽略限额"就破功了。

## 拴马桩怎么做

把钥匙和锁分开：

- **手机是执行者**：只负责识别并拦截你指定的 App 和内嵌信息流，界面上没有任何修改规则的按钮；
- **电脑是管家**：浏览器扫码配对一次，所有规则只在电脑上改。

```
电脑浏览器 ──局域网──► 手机内嵌控制台 (Ktor, :8765)
                          │  规则 / 应用组 / 冷静期 / 专注模式
                          ▼
                 无障碍服务
                 ├── T1 · 前台应用匹配（任意 App，按包名）
                 └── T2 · 应用内页面识别（微信视频号、直播）
                          │
                          ▼
                    勒马页（全屏拦截）
```

核心的不对称机制：

| 操作 | 生效方式 |
|---|---|
| **收紧**（调低额度、新增禁用） | **立即生效** |
| **放宽**（调高额度、解除禁用） | **10 分钟冷静期 + 120 秒确认窗口** |

管自己永远顺畅；放纵自己，永远要走到电脑前、再等十分钟。大多数冲动死在走过去的路上。

## 两级管控

| 层级 | 覆盖对象 | 原理 | 可靠性 |
|---|---|---|---|
| **T1 · 应用级** | 任意独立 App——抖音、B 站、YouTube、TikTok、Instagram、游戏，全都可以 | 前台包名匹配 | **永不失效**——App 改版不会改包名；完全不读取屏幕内容 |
| **T2 · 功能级** | 卸不掉的超级 App 内嵌信息流——微信视频号与直播，下一步：Instagram Reels | 窗口类名正则 + 屏幕关键词兜底，特征可热更新 | 依赖检测配置，微信改版后在控制台更新即可恢复 |

T1 服务所有人，T2 专攻最难啃的场景。哪怕微信某次大改版暂时废了 T2，所有 T1 额度照常生效，工具永不整体失灵。

## 功能特性

- 🎯 **任意 App 额度**——任何已安装 App 的每日限额与时段禁用；内置应用目录一键启用，也可手动添加任意包名
- 🧺 **应用组共享额度**——给整个"视频组"设一份每日总预算（如抖音 + B 站 + 视频号共享 45 分钟），刷任何一个都在消耗同一份；组内还可叠加单 App 独立上限
- 🕳️ **功能级拦截**——只拦视频号；微信聊天、朋友圈、公众号完全不受影响
- 🖥️ **电脑网页控制台**——手机在局域网内自托管（`http://<手机IP>:8765`），无云端、无账号、无埋点
- ❄️ **放宽冷静期**——防冲动核心机制，120 秒确认窗口过期自动作废
- 🔕 **深度专注**——电脑上一键锁死目标 45 分钟，期间一切放宽请求直接拒绝
- 📊 **用量看板**——按 App、按组的用量图表，拦截事件流水，CSV 一键导出
- 🔧 **检测配置热更新**——微信改版后，在控制台粘贴新特征即可恢复拦截，无需重装
- 🔒 **手机端只读**——手机浏览器打开控制台只见只读页，所有写操作一律 403

## 环境要求

- Android 8.0 及以上（minSdk 26），在 HarmonyOS / EMUI（华为）上开发与测试
- 微信 8.x（仅 T2 功能级拦截需要）
- 一台与手机同 Wi-Fi 的电脑（Windows / macOS 均可）

## 快速开始

### 1. 安装

从 [Releases](../../releases) 下载 APK，或从源码构建：

```bash
git clone https://github.com/<your-name>/mooring.git
# 用 Android Studio 打开 → 运行到手机
```

### 2. 手机端初始化（一次性）

应用内引导页分三步，每步自动回检：

1. 开启**无障碍权限**（设置 → 辅助功能 → 已安装的应用 → Mooring）
2. **保活设置**（华为）：设置 → 应用和服务 → 应用启动管理 → 手动管理三项全开；多任务界面下拉**加锁**
3. 屏幕上出现**配对二维码**，保持此页面

### 3. 电脑配对

电脑浏览器（同一 Wi-Fi）打开 `http://<手机IP>:8765`，页面会请求使用摄像头——对准手机上的二维码即可。扫码全程本地完成（jsQR），令牌只保存在电脑浏览器里。

### 4. 完成

默认规则开箱即用：**视频组——所有已启用的视频 App 加微信视频号——共享每天 45 分钟、09:00–22:00 禁用；视频号直播永久禁用；微信聊天永远不受影响。**

当初绝望卸掉的抖音？可以装回来，放进组额度里。拴马桩主张配额，不主张戒断。

## 检测原理

两级特征全部外置于 `detector_config.json`：

- **T1** 只监听前台窗口切换并匹配包名——屏幕上的任何内容都不会被读取；
- **T2**（仅微信）双信号识别：窗口类名正则匹配 Finder 系列 Activity（100ms 内）；节点关键词（"视频号 / 推荐 / 直播中"等）兜底覆盖朋友圈内嵌视频等入口。节点文本只做内存中的关键词匹配，用完即弃——不存储、不上传。

## 故障排查

| 症状 | 处理 |
|---|---|
| 不拦截了 | 检查无障碍开关是否被系统静默关闭；检查保活（启动管理 / 多任务加锁） |
| 微信更新后视频号拦截失效 | 在控制台上传新的 `detector_config.json`（设置 → 检测配置）；期间 T1 额度照常生效 |
| 控制台打不开 | 确认同一 Wi-Fi、端口 8765；手机 IP 可能变了（DHCP），重新扫码 |

## 隐私

- **零云端、零账号、零埋点**，所有数据仅存于本地 Room 数据库；
- T1 永远不读屏幕内容——它只知道前台是哪个应用；
- T2 仅在内存中做屏幕节点关键词匹配，匹配后立即丢弃；
- 内嵌服务只监听局域网，未配对客户端一律拒绝。
